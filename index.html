How the conversion works

The converter works in four stages, all running in your browser.

  1. Parse the file

    Cross-reference tables and streams, object streams, compression filters, fonts and images are decoded by pdf.js.

  2. Interpret each page

    A table maps every drawing operator (move, line, curve, fill, clip, text, image) to a handler, with a graphics-state stack.

  3. Build objects

    Handlers send paths, gradients, glyph outlines, bitmaps and layers to a canvas that collects editable objects. Clips are resolved and tiling patterns are expanded.

  4. Write the .cdr

    Objects become CorelDRAW X5 records (loda, fild, outl, trfd) in a zlib-compressed RIFF stream inside the ZIP container.

What comes across

PDF contentIn the .cdr file
Paths, rectangles, curvesEditable curve objects with exact Bézier nodes
Fills and outlinesUniform fills and outlines: width, caps, joins and dashes
Axial and radial shadingsLinear and radial fountain fills. Two-circle shadings become simple radials
Constant opacityUniform transparency
Images and image masksBitmaps, with an alpha mask where the PDF has one
TextCurves traced from the embedded glyph outlines. Invisible OCR text is skipped
Optional-content layersNamed CorelDRAW layers, and hidden ones stay hidden
Clipping pathsApplied to the shapes. Clipped strokes and images are kept whole
Tiling patternsExpanded into tiles, up to 400 per fill
Blend modes and soft masksImported as normal blending without the mask

The output is a CorelDRAW X5-format document (version 1500). Files open in CorelDRAW 2026 (tested November 2026), and each record layout matches files CorelDRAW itself saves in that format. Output is also checked with libcdr, the open-source CDR reader used by LibreOffice and Inkscape. Built with pdf.js (Apache-2.0), fflate (MIT) and Clipper2 (Boost). Not affiliated with Corel.
